# Summary: OpenAI founder admits AI isn't working
[Mo Bitar — OpenAI founder admits AI isn't working](https://www.youtube.com/watch?v=ZugX7a99dLk)

## Summary

Mo Bitar examines a recent interview with Andre Karpathy that exposes a fundamental contradiction at the heart of the AI coding tool narrative: Karpathy claims he no longer needs to review AI-generated code because the models have improved to the point of trust, yet simultaneously describes getting "heart attacks" when actually inspecting the output, calling it "bloaty," "copypaste-heavy," and filled with "awkward Python."

Bitar frames this as evidence that the current AI coding paradigm is broken. Karpathy describes a workflow where he gives specifications to an LM-based agent, then has to manually extract and copy-paste the best parts of the output because the agent is "very bad at reading code." He calls the process "very frustrating" and admits the quality is "not there yet."

## Key Points

- Karpathy's workflow involves writing specifications first, then having an LM agent generate code
- He describes having to "pull the pieces out of there and paste them" because LM agents are bad at reading code
- The output is described as "bloaty," filled with copypasta, and containing "awkward Python"
- Bitar argues this exposes the core problem: building better LM architectures isn't solving the fundamental issue
- The interview touches on the data distribution problem -- agents are getting worse over time as they're fed their own outputs
- Karpathy suggests hiring should shift from leetcode to spec-writing ability, as that becomes the bottleneck

## Commentary

Bitar's angle is clear: the promise of AI coding tools is that they'll eliminate the need for human code review, yet the most vocal proponents admit they still spend most of their time sorting through poor AI output. The fundamental issue isn't just quality -- it's that the architecture itself (LMs generating code from specs) doesn't preserve the original intent well enough to be trustworthy.
